Kimi K3 KDA Decode Fusion — Optimization Summary & Performance Comparison

PPU mega NVIDIA ref FLA k_last (predecessor)  · single-token decode · HV = H · D = 128 · bf16/fp16 activations · f32 state · generated 2026-07-30

Overview

Kimi K3 KDA decode fusion fuses short-conv → Q/K L2norm → per-channel decay gate → delta-rule recurrence → gated RMSNorm entirely into one CTA (1 CTA = 1 token × 1 v-head). This repository maintains three implementations side by side for development, regression and cross-checking:

  • PPU mega fused_kda_decode_ppu_kernel (src/fused_kda_decode_mega_kernel.cuh:118) —— the production version optimized for PPU1.5, pybind entry fused_kda_decode_mega_forward.
  • NVIDIA ref kda_decode_fusion_many_heads_kernel (src/fused_kda_decode_kernel_ref.cu:286) —— the NV upstream CUDA reference implementation ported back to the PPU platform, with signature/semantics identical to mega, dispatched internally from the same pybind entry via the environment variable KDA_DECODE_IMPL=ref.
  • FLA k_last fused_sigmoid_gating_delta_kernel (src/fused_sigmoid_gating_k_last_kernel.cuh:16) and its packed version —— the K3 predecessor from flash-linear-attention, doing only the recurrence (no short-conv, no RMSNorm); the "skeleton ancestor" of the mega kernel.

§1 PPU mega vs NVIDIA ref — optimizations made

The two have exactly the same fusion scope and grid granularity; the differences lie mainly in the memory hierarchy, warp specialization, the structure of the recurrence inner loop, and the use of PPU1.5-specific hardware instructions.

1.3 Stage-A (conv + L2 + gate) —— the biggest difference

ref's Stage-A only involves warps 0-3 (first if (tid < kDimK) computes q/k/decay, then if (tid < kDimV) computes v), leaving warps 4-7 idle for long stretches; PPU mega introduces WN8 warp specialization (P9):

  • Warps 0-3 handle the q + k channels (128 channels), while warps 4-7 simultaneously handle the v channels + per-channel decay. All 256 threads have work in Stage-A. (mega_kernel.cuh:265, 315)
  • The Q/K sum-of-squares reduction only runs on QK_WARPS = (WN8 ? 4 : WN) (:354); partials are stored in smem as float2 pairs (P6), so the later summation does 4 vectorized 8B loads instead of 8 scalar ones.
  • Only the q/k owner threads execute the final rsqrtf/scale, sparing the remaining 4 warps that work.
  • Sigmoid uses the PPU hardware instruction __ppu_sgmdf (ppu_sigmoid, mega_kernel.cuh:80-86); ref uses 1/(1+__expf(-x)).
  • The 3-tap conv-state writeback is fully equivalent to ref (compare kernel_ref.cu:404-409 vs mega_kernel.cuh:288-294).

1.4 Stage-B (recurrence core) —— algorithmic differences

refPPU mega
Outer loop 4 chunks × 4 rows / warp per chunk, paired-row (2 rows / iter) template parameter CORE_ROWS ∈ {2, 4}; quad-row (4 rows / iter) enabled when B·H ≥ 6144 (mega.cu:170)
Butterfly warp_reduce_sum_pair: a single XOR butterfly reduces 2 rows at once __shfl_xor_sync, reducing 2 or 4 rows each time; the result is ready in all lanes, no second broadcast needed
Legacy k_last pain point — both ref and k_last need a second __shfl_sync(..., 0) broadcast (the down-butterfly only gives the sum to lane 0); mega's xor-butterfly gives the sum to every lane, saving the broadcast outright
Output H is stored first, then q · H is computed o = q·S is computed immediately after S += k⊗v_new; the state is written back with the PPU wide store Global v4float (mega_kernel.cuh:495, 583)
Prefetch overlap issued once at the chunk boundary issue_async_stage for the next stage inside each pair (or quad) iter, fully overlapping this round's FMAs (:484, 567-570)

1.5 Stage-C (gated RMSNorm epilogue) —— fewer barriers

  • ref: kAccumulateOnormSumsq=false (launched instance) first stores s_o[tid], then block_reduce_sum, for 3 barriers total. kPreloadOnormParams=true loads gate·sigmoid and norm_weight early in Stage-A to hide global latency.
  • mega (P3): each warp writes the sum of squares of its own o_reg[] to smem_reduction[warp_id], does one __syncthreads(), and then each consumer thread redundantly recomputes the sum from the 8 partials in registers —— in exchange for 1 barrier. gate / norm_weight are not preloaded; they are read at writeback time and rely on L1/L2 hits. (mega_kernel.cuh:615-676)

1.7 Tunable parameters (mega production menu)

mega can be overridden via the KDA_WN / KDA_SN / KDA_CR / KDA_PE env vars; when unset it selects automatically:

  • WN ∈ {4, 8}, default 8.
  • SN (pipeline stages) ∈ {3, 4, 5, 6}, default 4; 3 when B·H ≥ 1536; 4 when CORE_ROWS=4.
  • CORE_ROWS ∈ {2, 4}, default 4 if and only if B·H ≥ 6144, otherwise 2.
  • PE (parallel epilogue) defaults to the P7 parallel version, unless APPLY_ONORM && num_ctas=384.
  • Instantiated combinations (mega.cu:185-193): {8,4,2}, {8,3,2}, {8,5,2}, {8,6,2}, {8,4,4}, {4,3,2}, {4,4,2}, {4,5,2}, {4,6,2}.

1.8 PPU1.5 hardware specifics

  • __ppu_barrier_sync_defer(0, WN·32, 1) —— a "deferrable" barrier for the recurrence, used at the AIU consume point to avoid a whole-block __syncthreads (mega_kernel.cuh:449, 536).
  • Global v4float wide store —— the PPU uncached global store form, used to store h0 (:495, 583-587).
  • AIU is issued by warp 0 alone with bulk-load semantics (:222, 644); the other warps keep computing during the DMA.
  • The PPU_KDA_USE_AIU macro brings PPU1.0 onto the AIU path as well (arch-100 asm variant); only non-PPU CUDA takes the cp.async fallback.
  • No __launch_bounds__: the quad-row core uses 80 registers / 75% occupancy, which a large grid more than offsets.

1.9 Template switches ref has but mega deliberately drops

ref has 15 k* template bools (kernel_ref.cu:276-284); mega keeps only 4 (APPLY_ONORM, USE_LOWER_BOUND, PARALLEL_EPILOGUE, CORE_ROWS) + runtime-tuned WARP_NUM, BV, STAGE_NUM. Key items dropped:

  • kUpdateConvState=false —— the "do not write the conv cache" codepath is no longer provided.
  • kApplyBetaSigmoid=false —— raw beta is no longer provided.
  • Specialization switches such as kUseStaticDecodeLayout, kFixedHeads and kUseHeadGrid are all folded into hard-coded dispatch.

2.2 Layout / interface changes

  • Input layout: k_last uses separate q[B,T,H,K] / k[B,T,H,K] / v[B,T,HV,V]; k_last_packed uses mixed_qkv[B, 3·H·K]; mega uses the pre-conv x[B, 3·H·128] plus a taps tensor.
  • New tensors: weight[3,4,H·128] (short-conv weights), conv_state[slots, 3·H·128, 3] (conv history, tap-major), dt_bias[H·128], output_gate[B,H,128], norm_weight[128], norm_eps.
  • In-place contract: mega allocates no outputs and writes conv_state / state / out entirely in place (mega.cu:353-355); k_last calls torch::empty(...) itself.
  • State sharing: state_indices addresses both the conv state and the recurrent state (mega_kernel.cuh:36-37); this is part of the vLLM paged cache contract.
  • H = HV (the single K3 scenario): mega assumes HV_PER_CTA=1; k_last keeps the multi-v-head-per-CTA v-tiling.
  • Grid indexing: k_last uses divide_by_power_of_two(blockIdx.z, H) (assuming H is a power of 2); mega uses blockIdx.z = batch, blockIdx.y = head directly, supporting K3's 12/24/48/96.

2.3 Algorithmic differences in the recurrence core (Stage-B)

k_last single-row core (k_last_kernel.cuh:344-429, simplified):
  for hv_step:
    for v_i in 0..V_ITERS:              # <- 1 row / iter
      cp_async_wait<SN-1>
      h *= bg; v_delta = h · k          # <- single-row dot product
      __shfl_down_sync butterfly
      v_delta = __shfl_sync(..., 0)     # <- needs a second broadcast from lane 0
      h += k * v_new
      global store h
      o = h · q
      __shfl_down_sync butterfly
      if (lane_id == 0) o[...] = o_val  # <- only lane 0 writes

mega Stage-B (CORE_ROWS=2, mega_kernel.cuh:521-613, simplified):
  for hv_step:
    for v_pair in 0..V_ITERS step 2:    # <- 2 rows / iter (P5)
      cp_async_wait<SN-2>
      h_a, h_b = smem[stage_a], smem[stage_b]
      h_a *= bg; h_b *= bg
      vd_a, vd_b = h_a·k, h_b·k
      __shfl_xor_sync reduces 2 rows at once  # <- XOR-butterfly: result ready in all lanes
      v_new_a, v_new_b = (v - vd) * b_beta
      issue_async_stage(next_a, next_b) # <- recurrence overlaps prefetch
      Global v4float store h_a, h_b     # <- PPU wide store
      o_reg[v_pair]   = h_a · q         # every lane has o
      o_reg[v_pair+1] = h_b · q         # consumed directly by the RMSNorm sumsq

Key differences:

  • Paired-row / quad-row: mega processes 2 or 4 rows per iter, cutting the butterfly and barrier counts to 1/2 or 1/4.
  • XOR butterfly instead of down butterfly: the result stays in all 32 lanes and is reused directly by the subsequent q·S and RMSNorm sumsq, saving one __shfl_sync(..., 0).
  • Register-resident o (o_reg[V_ITERS]): k_last global-stores at every step, while mega buffers it in registers for the P3 epilogue.
  • P7 parallel epilogue: staged into smem_o[BV], with a 128-way parallel Stage-C write (k_last has lane 0 write alone at every step).
  • Cheaper deferred barrier: k_last uses __ppu_barrier_sync_defer at single-row granularity; mega uses it at pair/quad granularity, cutting the number of triggers within a CTA to 1/2 or 1/4.
  • AIU CUBE_N=1: because mega has HV_PER_CTA=1, CUBE_N is always 1 and the AIU descriptor is simpler.

2.4 FLA codepaths removed / replaced

  • MTP_VERIFY branch (k_last_kernel.cuh:435-863, ≈430 lines) —— the whole Eagle-tree parent-token state cache / retrieve_parent_token_ptr path is obsolete in KDA decode fusion; mega only supports T = 1.
  • Generated dispatch headers (fused_sigmoid_gating_dispatch_k_last.h, get_tuned_k_last(_packed/_mtp)) —— replaced in mega by the hand-written KDA_DISPATCH_CFG macro (mega.cu:185-193).
  • bf16 ↔ f32 state conversion (fused_sigmoid_gating_cuda_k_last_packed.cu:86-97) —— mega requires the state to be f32 and updates it in place.
  • Template switches use_qk_l2norm, disable_state_update —— in the K3 scenario L2 is always on and the state is always updated, so they were hard-coded away.
  • PAD_SLOT_ID=-1 early exit (k_last_packed_kernel.cuh:59-71) —— mega instead relies on the caller guaranteeing valid state_indices.

§5 Exploration log: H-static-templating + kPreloadOnormParams (reverted)

2026-07-30 · card6 · 3 independent benches · conclusion: neither change brings a positive gain; both have been fully reverted.

5.1 Motivation

Two design patterns borrowed from the ref kernel:

  • kFixedHeads (H-static-templating): promote H from a runtime parameter to a compile-time template parameter kFixedHeads ∈ {12,24,48,96}, so that dim = H×128 folds into constexpr kDim and the conv tap stride 3*dim folds into constexpr kPackedDim; the host side gains a four-way switch(H) dispatch. The expectation was that the compiler would use constant propagation + loop unrolling to optimize address computation and the AIU descriptor more aggressively.
  • kPreloadOnormParams: preload sigmoid(output_gate) and norm_weight[v] into smem (2×128×4B = 1KB) during the spare bandwidth window of Stage-A (conv + SiLU), so that the Stage-C epilogue no longer issues gmem loads + sigmoid instructions, shortening the tail critical path. Modeled on the ref kernel's kPreloadOnormParams=true pattern —— but ref can preload directly into registers (the same thread owns the v-channel), whereas in PPU mega the WN8 Stage-A threads (tid 128-255) differ from the P7 epilogue threads (tid 0-127), so it has to relay through smem.

5.3 Root cause analysis

  • H-template brings no gain: on the critical path of the PPU mega kernel (the Stage-B recurrence), dim only appears in address offset computation (conv_w(w,hk,tap,dim), the 3*dim stride of the conv state writeback) and does not affect loop trip counts or register allocation. constexpr folding saves 1 integer multiply (H*128), which is invisible in a memory-bound kernel. Instead it introduces a new template instantiation axis (4 H values × the existing WN×SN×CR×ONORM×LB×PE), significantly increasing compile time and .so size.
  • kPreloadOnormParams brings no gain: the smem relay path needs an extra store + barrier + load, whose latency roughly cancels out loading directly from gmem (L2 hot). The ref kernel benefits because the same thread does a zero-overhead register-to-register preload; PPU mega's WN8 thread mapping does not allow that path.

5.4 Conclusion

As attempts to "align with the ref design patterns", both changes are not applicable on PPU1.5. The root cause is that PPU mega's thread mapping and memory-bound nature keep the theoretical advantages of both from materializing. Everything has been reverted to the baseline code. If a future PPU architecture offers wider L1/smem bandwidth or supports cross-warp register sharing, kPreloadOnormParams can be re-evaluated.
